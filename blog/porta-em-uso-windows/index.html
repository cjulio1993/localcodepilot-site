Porta 3000 em uso no Windows: como resolver

Erros como EADDRINUSE ou “address already in use” podem indicar que outro processo já está escutando na porta desejada. Antes de encerrar qualquer processo, descubra qual aplicativo ele representa. Os exemplos abaixo usam TCP e a porta 3000; substitua o número pela porta do seu erro.

1. Identifique quem está escutando

Abra o PowerShell e execute:

Get-NetTCPConnection -LocalPort 3000 -State Listen -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess

A coluna OwningProcess contém o PID. Podem existir entradas IPv4 e IPv6 para o mesmo processo. Sem resultado, não foi encontrado um listener TCP nessa porta no momento da consulta; o processo pode ter parado ou o problema pode ter outra causa.

2. Confira o processo pelo PID

Substitua 12345 pelo PID encontrado:

Get-Process -Id 12345 | Select-Object Id, ProcessName, Path

Se necessário, consulte a linha de comando para distinguir servidores com o mesmo nome:

Get-CimInstance Win32_Process -Filter "ProcessId = 12345" |
    Select-Object ProcessId, Name, CommandLine

Alguns dados podem exigir permissão adicional. Não publique linhas de comando sem revisar possíveis credenciais.

3. Pare o serviço conhecido ou escolha outra porta

Se for seu servidor de desenvolvimento, prefira Ctrl+C no terminal de origem ou a ação de parar no aplicativo responsável. Se não reconhecer o processo, não o encerre: escolha outra porta nas configurações do projeto.

Para um projeto que usa Vite por meio do script dev, um exemplo é:

npm run dev -- --port 3001

Essa opção depende do comando executado pelo script; não é um parâmetro universal do npm. Atualize também URLs de frontend, API e callbacks quando necessário.

Como último recurso para um processo seu, já identificado, o PowerShell pode solicitar confirmação antes de interrompê-lo. Isso pode descartar trabalho em andamento; o encerramento não substitui a parada normal do serviço:

Stop-Process -Id 12345 -Confirm

4. Verifique novamente

Repita a consulta da primeira etapa e reinicie seu projeto. Se o serviço reaparecer, verifique se existe um supervisor reiniciando o processo. Se a porta estiver livre e o erro persistir, revise o log completo, o endereço de bind e as configurações da aplicação.
