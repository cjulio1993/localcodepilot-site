How to organize local development projects

When you switch between repositories, finding the code is not always the hard part. You also need to remember which service to start, which port it used and where the last failure appeared. A simple opening and shutdown routine helps more than a perfectly named folder.

1. Choose a predictable root

Keep active projects under a root you recognize, for example C:\dev. Separate projects from temporary files, downloaded dependencies and build output. You do not need to move every repository at once: start with those you use this week.

In PowerShell, list immediate folders with Get-ChildItem -LiteralPath 'C:\dev' -Directory. This can reveal duplicate names and forgotten projects.

2. Keep startup instructions in the project

Record the required runtime, setup command, start command and expected URL in the repository README. If the project needs environment variables, document their names without publishing secrets. An example file can show the shape; real credentials should stay out of Git.

3. Check what is already running

Before starting another server, inspect the expected port. On Windows, Get-NetTCPConnection -LocalPort 3000 -State Listen -ErrorAction SilentlyContinue shows a TCP listener on port 3000, if one exists. Use Get-Process -Id 12345 with the returned PID to identify it. Leave unknown processes running; use the port conflict guide to investigate safely.

4. Start one service at a time and read the first error

When a service fails, start with the first useful error in the log. Check the runtime, dependencies, configuration file and port before repeating a command. If there is an HTTP health check, inspect the project's reported URL rather than assuming that a running process means the app is ready.

5. Close the loop before switching projects

Stop the service from the terminal or app that started it, record the next task in the repository, and check for any process still listening on the port. These small signals save time in the next session.
